ゆっくり解説動画風のアニメを作る基盤を作った — 声もBGMも絵も、その場で合成

RECORDED2026-11-23T23:50:00+09:00

プログラミングJavaScriptAI音響

ゆっくり解説動画風のアニメを作る基盤を作った — 声もBGMも絵も、その場で合成

これまでに作ったものを組み合わせて、ゆっくり解説動画のような、2人の掛け合いで難しいことを解説する3Dアニメーションを作る基盤を作った。ブラウザで再生できて、動画ファイルにも書き出せる。

組み合わせたのは、この3つ。

  • 声：OtoVoice。録音を使わない話し声の合成（11月22日の記事の追記に書いた）。口の動きは、声の大きさから決める。
  • BGM：テキスト譜スタジオの作曲の基盤、TextScore。
  • 絵：three.js。キャラクターは、前に作った3Dの頭のモデルの描き方を流用した。

見本の回は「GPSは相対性理論なしでは使えない？」（4分1秒、48セリフ）。解説役のノアと、聞き役のヒナが話す。顔はまんじゅうのような平たい丸で、髪・髪飾り・帽子を乗せている。どちらもこのために作ったキャラクターで、髪型や色、帽子はページで変えられる。使い方を説明する40秒の回も入れてある。こちらは新しい回の雛形を兼ねている。

→ Kaisetsu スタジオ

今回も Claude と作った。Claude は音を聴けないので、音まわりの数字は機械で測ったものだ。

1回 ＝ 台本 ＋ 場面のコード

最初は GPS の解説を、1本ものとして作った。見てみると良い感じだったので、使い回せる形に分けた。

  • kaisetsu.js（約100KB）：声、口の動き、字幕、ボード、ラベル、BGM、キャラクター、書き出し、台本チェック
  • 回のファイル：台本と、3Dの場面のコード

台本の1セリフは、こう書く。

{ w: 'A', s: 'sum', t: '合わせると、45引く7で、1日に約38マイクロ秒。',
  k: "あわせると、よんじゅうご ひく なな で、いちにちに やく さんじゅうはち まいく'ろびょう。",
  b: { h: '＋45 − 7 ＝ ＋38 μs／日', r: ['衛星の時計は、1日に約38マイクロ秒進む'] } },

w は話し手、s は場面、t は字幕、k は読み（ひらがなとアクセントの印）、b は左上のボード。表情も1セリフごとに付けられる。場面のほうは、three.js で物を置いて、場面ごとのカメラの位置と、物に付ける名前（ラベル）を返す関数を書く。

場面は、回ごとにAIが書く前提にした。題材ごとに見せたい物はちがうので、部品を用意して選ばせるより、毎回コードを書かせたほうが早い。書き方と決まりは、kaisetsu.js の頭にコメントで手引きとして入れてある。ただ、その手引きだけを読んだ別のAIが良い回を書けるかは、まだ試していない。

見た目の決まりを、台本の決まりにする

最初の版は、字幕の帯の高さがセリフの長さで変わっていた。説明の文字やラベルが重なるところもあった。

字幕は、2行分の高さで固定した。そのかわり、2行に入りきらないセリフは書けない、という決まりにした。

  • 字幕：全角48字まで、2行まで
  • 声：1セリフ9秒まで
  • ボード：見出し20字まで、3行まで、1行26字まで
  • ラベル：12字まで
  • 読み：OtoVoice が読めること

ページの「台本チェック」が、全セリフの字幕を実際に折り返して、声の長さも測って、決まりの外を一覧にする。読みの誤りは、OtoVoice の check() で拾う。GPS の回は0件で、いちばん長い字幕が43字、いちばん長い声が7.2秒。見た目で困ることを台本の決まりに落としておくと、AIが書いた台本を機械で弾ける。

画面の割りつけは、左上がボード、右上が章、下のまんなかが字幕、左下と右下がキャラクター。ボードは半透明にして、後ろの3Dが透けるようにした。ラベルは、ボード・字幕・キャラクター・ほかのラベルを避けて置き場所を探し、元の位置から離れたら細い線でつなぐ。

BGM は場面ごとに、セリフの間は下げる

BGM は TextScore で5曲書いた。はじまり（明るい）、説明（落ち着いた）、ふしぎ（考える）、緊張（時計の音）、解決（あたたか）。回のファイルで、場面ごとにどれを流すかを決める。どれも16〜23秒の曲で、ページを開いたときにブラウザで音にする。

ループは、譜面を2回くり返して音にし、2回目の頭から終わりまでを使う。こうすると、ループの頭にも、前の小節の残響が入る。1回分だけを音にしてループさせると、頭の残響がない。

セリフのあいだは、BGM の音量を自動で下げる。GPS の回の音を通しで書き出して測ると、BGM はセリフ中のほうが、セリフの間より4dBほど小さかった（中央値）。曲が場面の切りかわりで途切れていないことも、同じ音で確かめた。下げ方がちょうどいいかは、聴いて決めることになる。

動画ファイルに書き出す

書き出しは、再生と同じ予定表を使って、1コマずつ（30fps）描く。3Dと文字を1枚に重ねて、WebCodecs で VP9（WebM）か H.264（MP4）に圧縮する。音は OfflineAudioContext で、声と BGM を同じ予定表から作る。入れ物に詰めるのは webm-muxer と mp4-muxer（どちらも MIT）。

書き出しても再生と同じ動きになるように、場面の動きは「場面に入ってからの秒」と「頭からの秒」で決めることにした。コマの間隔に頼った動きは、描く速さで変わってしまう。

つまずいたのは1つ。書き出した動画の3Dが真っ黒だった。文字を描く関数が、最初に画面を消していた。再生では文字だけの層に描くので問題ないが、書き出しでは3Dを写した上に文字を描くので、3Dまで消えていた。

claude.ai の中では、ページが自分でファイルをダウンロードさせられないので、claude.ai の保存の機能を通す。ブログに置いた版は、ふつうのダウンロードにしてある。

できないこと

  • 耳では確かめていない。BGM の雰囲気、声と BGM の釣り合い、読みのアクセントは、聴いて直すことになる。
  • 書き出しは時間がかかる。GPU のない試験環境では、動画の長さの約8倍かかった。GPU のある端末では測っていない。
  • MP4 の音は、AAC を作れないブラウザでは Opus になる。Opus 入りの MP4 を再生できないソフトもあるかもしれない。困ったら WebM で。
  • 確かめたのは Chrome 系のブラウザだけ。Safari と Firefox は試していない。
  • 解説の数字（衛星の時計が1日に約38マイクロ秒進む、など）は、一般に言われている値を使った。

追記（11月24日）

VTuberのゲーム実況みたいなやつも作ってみた。自作のゲームを自動の遊び手が遊んで、VTuberがしゃべりながら配信している風の動画を、ブラウザの中で作る。

  • 画面：左に大きくゲーム、右下にVTuber（腰から上）、右上に視聴者の書き込み、下に字幕。書き込みの名前は、ぜんぶ作りもの。
  • VTuber：自作の3D麻雀「翠卓」の8人をそのまま使った（頭と髪は Claude、服は GPT-6 Astra がフルスクラッチで書いた。肩・肘・手の関節や手のつくりは、自由に使える VRoid のモデルを参考にしている）。声は OtoVoice で、しゃべると口が開く。
  • ゲーム：上空 左旋回・射手、上空・射手、✕✕サーキット 午前二時・周回の3本（サーキットは24日の夜に足した）。遊び手は、外したり、被弾したり、後ろを撃とうとして止められたり、ブレーキが遅れてふくらんだり、たまに失敗もする。
  • 掛け合い：「ズームってできるの？」と書きこまれると、答えてから実際にズームする。英語の無線を「なんて言ってるの？」と聞かれると、ゲームの字幕を言いかえて答える。

最初の版は、エイムが急で画面酔いしそうだった。測ってみると、ねらいを移すときに毎秒200°近くで振っていて、真後ろを向いたところでは画面が1こまで70°以上跳ぶこともあった。手の速さと加速度に上限を置き、止まれる距離から逆算して減速するようにして、ふだんは毎秒50°くらいまでに抑えた。

録画もできる（実時間なので、1本7〜11分くらいかかる）。今回も、声とゲームの音の釣り合いは、聴いて直すことになる。

追記（11月25日）

怪談の回を足した。「玄関の靴を数えてはいけない」（4分半、59セリフ）。語りのノアが、子供のころに住んでいた古い借家の、玄関の話をする。

  • 入り口は、脱いだ靴を外向きにそろえる「出船」と、内向きの「入船」の話。
  • 解説用の部品を、そのまま怖がらせる道具にした。物に付けるラベルが靴を数え、夜ごとの足あとを数え、最後は近づいてくる靴の歩数を数える。左上のボードも、最後は真顔で「決まり」を並べる。
  • BGM は怪談用に4曲書いた（わらべうたのオルゴール、夜の玄関、心臓の音、子守唄）。和室の場面だけ、わざと無音にしてある。BGM もちゃんと怖い。
